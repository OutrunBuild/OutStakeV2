对当前工作区相对 HEAD 的全部未提交改动（tracked 修改 + untracked 新文件；排除 docs/superpowers/ 等被 gitignore 的设计记录）进行循环多轮 Review。

核心铁律：Review-only，严禁修复。全程不得 Edit/Write 任何 src/test/script/docs 代码、spec 或 .harness 配置；不得 git add/commit/push；唯一允许写入的是下述审查报告文档本身，以及每轮由 review-package.sh 生成的临时审查包。被派发的 subagent 同样只读、不改文件、不跑修复。

审查范围与归因规则：
- 审查包列出的相对 HEAD 未提交改动是每轮主审查对象。
- 为核对改动影响，主会话与 subagent 可只读查看审查包之外、和改动直接相关的既有 src/、test/、docs/spec/、接口、调用方及配置。
- 既有缺陷也必须作为 finding：交叉核对发现的、可独立复现或能以严密状态推导证明的既有正确性、产品语义、不变量、权限、资金流或安全缺陷，不因其位于 HEAD 基线而排除。
- 每条 finding 必须明确标注归因：
  1. `本次改动引入/加剧`：必须引用审查包中的具体 diff 片段，并说明该变更如何触发、扩大或暴露问题。
  2. `既有缺陷`：必须引用 HEAD/基线中的具体代码片段，并注明关系为“直接相关”或“交叉核对发现、独立存在”；不得伪称由本次改动引入。
- `本次改动引入/加剧` finding 必须含审查包 diff 证据。
- `既有缺陷` finding 必须含基线代码证据；如与本次改动有交互，再补充审查包 diff 证据。
- 两类 finding 都必须给出 `输入/状态 → 错误输出、revert、权限绕过、资金错配或不变量破坏` 的可验证触发路径或状态推导，并锚定 `文件::符号名`。
- 不得因 finding 不在 diff 中而丢弃既有缺陷；不得将既有缺陷错误归因给本次 diff。
- 与本次改动没有直接关系的既有缺陷可以报告，但必须标注为“交叉核对发现、独立存在”。

每轮流程（每轮完全相同，固定同一组角度、每轮全覆盖、不轮换）

1. 获取审查包（diff 较大，按路径传递，不贴进上下文）
- 第 1 轮：先根据 git status 得到改动文件清单，再运行：

bash script/harness/review-package.sh HEAD <pkg.md> --files <由 git status 得到的本轮改动文件清单>

生成审查包（含 tracked 改动 + untracked 新文件全量），记下包路径。
- 后续轮：Review-only 循环不修改工作树，审查包内容逐字节相同，不得重新生成，直接复用上一轮的包文件；仅当 `git status --porcelain` 显示文件清单与上一轮不同（如人工中途修了代码）时才按上述命令重新生成并更新包路径。
- 每轮把包文件路径传给各 subagent，不要把 diff 内容贴进 dispatch prompt。

2. 并行派发 5 个 subagent（同一条消息并行，每个一个角度）
每个 subagent 先读审查包，再仅返回 raw candidate dump（confirmed + borderline + 已否决及理由，三者均可为空）。允许空 dump：一轮中确认 0 条、borderline 0 条是正常结果，直接返回空列表即可；严禁为凑数而制造候选。固定角度：

- A 正确性与合理性：语义、边界、状态转换、与 docs/spec 一致性。
- B 优雅与简洁：代码优雅性（架构设计、可维护性）与 Gas 优化点。Gas 类候选须按 docs/prompts/finding-impact-scheme.md 证据门执行：必须带 static:/measured: 证据，需 benchmark 或编译器输出才能判定的降为 candidate，不成 finding。
- C 遗漏：边界/路径/错误/事件/测试覆盖缺口。
- D 跨模块破坏：是否破坏既有产品语义/功能/不变量/权限/资金流（对照 docs/spec 与既有 src）。
- E 逻辑与安全漏洞：重入、溢出、访问控制、CEI、flash/unlock surface、升级安全。

每个 subagent 的 dispatch prompt 必须显式包含以下约束：

“Review-only。不得 Edit/Write，不得运行修复命令，不得 git add/commit/push。先读取给定审查包；可只读打开审查包外、与改动直接相关的既有 src/、test/、docs/spec/、接口、调用方及配置以交叉核对。审查包列出的未提交改动是主审查对象，但发现可验证的既有缺陷也必须返回。所有候选均须锚定 `文件::符号名`，并按 `本次改动引入/加剧` 或 `既有缺陷` 标注归因。前者必须引用审查包中的具体 diff 片段；后者必须引用基线代码片段，并说明与本次改动的关系。候选须按 docs/prompts/finding-impact-scheme.md 定维度、定档并写出 Impact Statement；写不出 Impact Statement 或命中排除清单的候选放入 rejected 并注明理由。返回 raw candidate dump：confirmed、borderline、rejected；每个 rejected 必须附否决理由。不得遗漏已否决项。”

3. 本轮去重 + 验真（主会话执行，不轻信 subagent）
- 本轮去重：多个角度命中同一问题的合并为一。
- 逐条核对证据。
- 影响评判：按 docs/prompts/finding-impact-scheme.md 锚表定维度、定档（Blocking/Major/Minor/Info），再按 Reachability（无条件/有条件/高门槛/假设路径）修正，只降不升。确认前必须写出 Impact Statement（谁 × 什么状态下 × 哪个维度 × 程度多大）；写不出 → 丢弃。命中排除清单（个人风格、行数削减、投机性 Gas、无证明的理论影响、不掩盖真实 bug 的测试覆盖缺口等）→ 丢弃并记录理由。既有缺陷（预存问题）与本次改动引入的问题适用同一评判，不因位于基线而降档或丢弃。
- 对 `本次改动引入/加剧`：必须贴出审查包中的具体改动片段，并给出 `输入/状态 → 错误输出/crash/资金错配/权限绕过/不变量破坏` 的触发路径或状态推导，锚定 `文件::符号名`。
- 对 `既有缺陷`：必须贴出基线中的具体代码片段，并给出同样可验证的触发路径或状态推导；若和本次改动存在交互，补充审查包片段。
- 无法自证为真的、证据矛盾的或无法建立触发路径的候选丢弃并记录理由。
- 必要时运行只读 forge build、forge test --match-path 或 grep 进行交叉核对；不得修改代码。

4. 跨轮去重（finding 混合，不按轮分桶）
读取报告文档累积 finding 列表：
- 与历史 finding 语义等价的候选不重复写入。
- 历史 finding 是既有缺陷不构成排除理由；只有同一问题已被历史记录时才去重。
- 同一根因（同一底层缺陷）在本轮命中了新的触发条件、影响或修复落点时，不新增 finding，而是把新增的触发路径、影响与修复落点并入原 finding 的对应字段，发现轮次追加本轮；若本轮衍生由本次改动触发、扩大或暴露，归因升级为「本次改动引入/加剧」并补审查包 diff 证据，否则保持原归因。
- 累积列表里的 finding 跨轮混排，只保留发现轮次作为元数据；批次划分以全量累积 finding 为输入，不按轮切片。

5. 写入报告（追加，若没有则先创建）
追加到同一个中文文档：

docs/review/multiround-review.md

`docs/review/` 已 gitignore，不影响 git。报告为累积单一结构，不按轮切片；每轮只把新增 finding 追加进同一列表并刷新批次表。结构含：

- 累积 finding 列表（跨轮混合，不按轮分组；每条记录发现轮次作为元数据）。每条包括：
  - 编号；
  - 归因：`本次改动引入/加剧` 或 `既有缺陷`；
  - 既有缺陷与本次改动的关系：直接相关 / 交叉核对发现、独立存在；
  - 发现轮次；
  - 贡献角度；
  - Impact 档位、Reachability 级、Impact Statement；
  - 问题；
  - 证据：代码片段、触发路径或状态推导、`文件::符号名`；
  - 建议修复方向；
  - 修复落点文件；
- 丢弃项摘要：条目和理由（本轮新增）；
- 批次划分：见第 6 步，每轮基于全量 finding 重算；
- 明确声明：本轮未修改代码；后续轮次应深化寻找前轮遗漏的新问题。

6. 批次划分（跨轮按修复落点文件分组）
批次以"修复落点文件"为唯一分组键，跨轮混合所有已确认 finding 重新计算：
- 同一批内的 finding，修复落点文件必须两两不同（同一文件只能出现在一个 finding 的落点里，避免改同一文件冲突）。
- 落点文件相同的多个 finding，拆到不同批。
- 不使用"串行/并行"字样。批次命名 `批 1 / 批 2 / …`，每批列出所属 finding 编号与其落点文件列表，落点文件互不重叠即可。
- 落点文件含多个文件的 finding：只要该 finding 的任一落点文件与同批其它 finding 的任一落点文件相同，就视为冲突，拆到不同批。
- 既有缺陷和本次改动引入/加剧的问题一并纳入批次划分，保留各自归因标签。
- 每轮刷新批次表（基于全量累积 finding），供后续人工修复参考。
- 本轮不改代码。

停止条件：
- 循环轮次上限 12 轮，达到上限立即停止（即使尚未满足其它停止条件）。
- 当连续两轮“跨轮去重后且验真为真”的新问题数均为 0，停止（仅一轮为 0 不足以停止；中间任一轮出现新问题即重新计数，需重新积累连续两轮为 0）。新问题计数只统计 Blocking/Major/Minor；Info（已证明但可忽略）不重置计数。
- 否则（轮次未达上限）重派同一组 5 个角度（复用现有审查包；仅当文件清单变化时按第 1 步重新生成），继续下一轮。
